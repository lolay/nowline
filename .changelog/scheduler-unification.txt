```release-note:fixed
**`@nowline/layout` + every surface — the date window of a roadmap whose isolated include declares its own sizes now uses those sizes** ([`specs/scheduler-unification.md`](./specs/scheduler-unification.md) §3.3, §8 decision 2): in a roadmap without waves, the window resolved the items of an `include "…" roadmap:isolate` region against the parent's sizes, so an item whose size only the included file declares counted as no time. The window now comes from the day schedule, which uses the region's own sizes, the ones its bars were already drawn with (roadmaps with waves already did). The axis still grew to cover those bars after placement, so most renders are unchanged; what changes is the layout decided against the short window, such as a now-line within the region's work on a roadmap with `length:` now getting its pill row. No example, test fixture, snapshot or determinism cell changes.
```

```release-note:changed
**`@nowline/layout` + every surface — `after:` on an item, group or parallel in a swimlane or group no longer starts it before the previous item in its lane ends** ([`specs/scheduler-unification.md`](./specs/scheduler-unification.md) §5 F1, §8 decision 3): the chart started such a child at the latest of the lane's left edge and its references, so `after:x` could place an item over its predecessor whenever `x` ended earlier. It now starts at the later of the previous item's end and every reference's end, so `after:` only ever delays. This is the rule the XLSX, MS Project and Mermaid exports already used, so the chart and the exports now agree on the order of a lane's items. A bar can still sit a couple of days after its export date where a group inside a parallel adds its tail gutter. Among the examples and fixtures, the showcase (`Ship` now follows the parallel block it waits on instead of starting on day 20; it sits about two days after the exports' date because of that gutter), `sizing` and `tests/late-row-shifts` change; every other sample renders as before.
```

```release-note:added
**`@nowline/layout` and `@nowline/export-core` — `LayoutOptions.schedule`, `ExportInputs.schedule`, and the wave plan, source roadmap and date extent on `RoadmapSchedule`** ([`specs/scheduler-unification.md`](./specs/scheduler-unification.md) §3.2, §3.6): `layoutRoadmap` reuses a `RoadmapSchedule` passed as `schedule` when its `resolved` is the same `ResolveResult` it lays out, and builds the wave plan and the schedule once itself when none is passed or the schedule came from another `ResolveResult`. `ScheduleOptions.plan` accepts a wave plan the caller already built (`null` for "built, no waves"), and `RoadmapSchedule` now carries `plan`, `resolved` and `extent` (`ScheduleExtent.contentEndDay`, the working-day offset of the latest content the date window needs). `ExportInputs` gains an optional `schedule`, which the export kernel fills so the XLSX, Mermaid and MS Project exporters read the schedule and wave plan the layout used instead of building them again; an exporter given inputs without one schedules the roadmap itself. Existing callers are unaffected.
```
