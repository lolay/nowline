# Changelog

All notable changes to Nowline are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Packages in this monorepo share a single version and ship together. Contributors append entries to `## [Unreleased]` as part of their PR; maintainers move them into a new `## [vX.Y.Z]` section as part of the release-cut commit (see [`specs/releasing.md`](./specs/releasing.md#changelog-workflow)).

## [Unreleased]

### Added

- **`@nowline/core` — waves: `wave` declarations and the `wave:` property** (milestone m2o, [`specs/waves.md`](./specs/waves.md)): a roadmap can declare ordered waves (`wave build "Build"`, optionally `after:<anchor | dated milestone | YYYY-MM-DD>` as a start floor), and `item`, `group` and `parallel` join one with `wave:build`, inherited by descendants. A wave is a strict barrier across every swimlane: no item in the next wave starts before every item in this one has ended. `wave` is a new keyword, but the bare word stays a valid identifier and value everywhere a v1 file could already use it (`item wave`, `after:wave`, `labels:[wave]`, `style:wave`), and the JSON AST of existing files is unchanged. The canonical printer prints wave declarations and orders `wave:` between `owner:` and `after:`.
- **`@nowline/core` — wave validation (NL.E1100–E1106, NL.W1100–W1101, NL.W0702)**: the validator checks wave declarations (a wave needs an id; `before:`, `date:`, `duration:` and other span keys are rejected; a wave's `after:` accepts only anchors, dated milestones or one ISO date), `wave:` values (exactly one wave declared earlier, only on `item` / `group` / `parallel`, a descendant cannot disagree with its container, never on a `default` line), and the wave order. NL.E1103 reports work that could never start because the lane or group order, an `after:`, a parallel join, or a chain through background work forces it past the end of its own wave, once per root cause with the fix in the message. NL.W1100 flags a `before:` the waves make impossible to meet, and NL.W1101 flags `after:` / `before:` references layout ignores (later swimlanes, later in the same flow, floating milestones, an enclosing container), which matter more once waves move every lane's columns. Messages ship in English and French. `@nowline/core` exports the pure rule functions (`checkWaveDeclarations`, `evaluateWaveProperties`, `evaluateWaveOrder`) and membership helpers (`ownWaves`, `effectiveWave`, `leadWave`, `assignWaves`, `waveFloorDate`) for the include resolver, layout and editors.
- **`@nowline/core` + `@nowline/export` + `@nowline/cli` + `@nowline/browser` + `@nowline/mcp` — waves across includes (include rule 12, NL.E0202, NL.W0701)**: every `merge` or `isolate` include that carries a roadmap, swimlanes or waves must declare the same waves, in the same order, with the same resolved start floors as the file that includes it (NL.E0202, reported on the `include` line; both directions are errors). A wave whose title or presentation differs is a warning (NL.W0701) and the including file's definition wins. Waves never merge, so diamond includes produce no shadow warnings. The include resolver also runs the wave rules on included files, which are parsed without validation, and runs the wave-order check over the merged lanes and each isolated region, reporting at the included file's path and line. Coded resolver diagnostics (`ResolveDiagnostic.code` / `args`, plus a `rule: 'wave'` marker) are reported like validator diagnostics everywhere: `nowline` exits 1 with the file and line, includes them in the `--diagnostic-format json` document and localizes them with `--locale`; `--serve`, the browser diagnostics table and the MCP `validate` / `render` / `export` tools show them with their codes. Include errors without a code (a missing file, a circular include, a `start:` mismatch) keep their exact output and exit 3, and take precedence when both occur. `@nowline/export` adds `IncludeResolveError` and an `onResolveDiagnostics` input; `@nowline/core` exports `buildWavePlan`, `localizeResolveDiagnostic` and `isRoutedResolveDiagnostic`.
- **`@nowline/layout` — wave barriers in the schedule (NL.W1001, NL.W1002, NL.I1006, NL.I1007)**: layout places every member of wave k+1 at or after the end of every member of wave k, across all swimlanes and isolated include regions, so a wave opens for every lane at the instant the slowest member of the previous wave ends and lanes that finish early idle at the boundary. Items with no wave are background work: never held back, never extending a wave, but still pushing later items in their own lane. A wave's `after:` floor holds its start back to an anchor, a dated milestone or a date, leaving a gap. `after:<wave>` means the end of that wave, so a floating `milestone … after:build` sits exactly on the boundary; wave references draw no dependency or slack arrows. The pixel layout, the date-window sizing and `scheduleRoadmap` (used by the XLSX export) apply the same barrier, and a wave past `length:` grows the window. The positioned model gains `waves` (span, dates, member count, the member that holds each barrier, the floor that set a gap) and `waveSolve`, items gain `waveRole` (`member` / `background`), and milestones gain `onWaveBoundary` / `overrunByWave`; `RoadmapSchedule` gains `waves`. New layout insights: a barrier moved an item's date pin (NL.W1001), the barrier passes did not settle (NL.W1002), empty waves (NL.I1006), and a wave overrunning a dated milestone that waits for it (NL.I1007). Roadmaps without waves lay out exactly as before.
- **`@nowline/layout` + `@nowline/renderer` — waves in the picture**: a roadmap with waves gets a 20 px wave strip under the date header, with one cell per wave (title, falling back to the id, a shortened title, then `#k` when the column is narrow; a tooltip with its dates and the member that holds the barrier), and a 2 px teal boundary line at every barrier from the strip down through the last lane. Lanes that finish early show their idle time up to the boundary. Background work (items without a wave) is hatched, with a dashed crossing mark where a boundary runs across it and a `Background (no wave)` tooltip. An empty wave is a hollow diamond in the strip, a start-floor gap shows its floor reference, and a roadmap whose waves have no items yet shows a placeholder. A milestone that sits exactly on a boundary keeps its diamond but drops its cut line; a dated milestone a wave overruns keeps its red one. A wave's `style:` can tint its column (`bg`), colour its boundary (`fg`), set its label colour (`text`) and dash its boundary (`border`). An untitled, unstyled `group wave:x` draws nothing, no bracket and no label, even when it has an id. A legend under the chart explains the hatch and boundaries and lists the waves when a label is shortened or a wave is empty. Isolated include regions re-draw the boundaries inside their box. New theme tokens (`theme.wave.*`) in light, dark and grayscale, with contrast tests; the hatch carries over to PNG and PDF. SVG output for roadmaps without waves is byte-identical.
- **`@nowline/export-xlsx` + `@nowline/export-mermaid` + `@nowline/export-msproj` — waves in the exports**: in a roadmap with waves, the XLSX Items sheet gains a `Wave` column after `Parallel` (each item's effective wave, blank for background work) and a last `Waves` sheet (ID, Title, Order, Start, End (exclusive), Items, Held by, After, Description) dated from the same barrier schedule the picture uses. Mermaid gains a `section Waves` of wave-end milestones before the lanes, and members of each later wave start `after` the previous wave's end; wave start floors can't be expressed and are counted in the `%%` drop summary. MS Project gains one zero-duration `(wave end)` milestone task per wave, finish-to-start links from each wave's members to its end and from each wave's end to the next wave's members, and `after:<wave>` links to the wave-end task; an anchor or dated-milestone start floor becomes a predecessor of the wave's members and end task, while inline-date floors and members without an id are counted in the lossy summary (`wave-floor`, `wave-member-no-id`). Exports of roadmaps without waves are byte-identical.
- **`@nowline/lsp` + VS Code extension — editor support for waves**: go to definition, find references and rename work from a `wave` declaration and from `wave:`, `after:`, `before:` and `on:` references (renaming `wave wave` edits the id, not the keyword); `wave:` completes the declared waves in order and `after:` / `before:` / `on:` completion includes them; waves appear in the document outline; hovering a wave shows its position (`wave 2 of 3`), title, labels, description and member count, and hovering an item shows its wave, where it inherits it from, or `background (no wave)`. The TextMate grammar colours `wave` as a keyword only at the start of a declaration line and `wave:` as a property key; new `wave` and `item-wave` snippets.
- **`@nowline/mcp` + `nowline(5)` — waves in the reference**: the MCP `schema` tool lists `wave` as an entity type and an item property key, and the condensed `reference` gains a Waves section. The `nowline(5)` man page (en and fr, also served as the MCP full `reference`) documents the `wave` declaration, the `wave:` property and its inheritance, wave ids as `after:` / `before:` / `on:` targets, include agreement, the `default` ban, and every wave diagnostic code.
- **`@nowline/layout` + `@nowline/renderer` + `@nowline/export-msproj` + `@nowline/core` + `@nowline/lsp` — `\n` in an item title forces a line break** ([#60](https://github.com/lolay/nowline/issues/60)): `item tech "Technology\nSelection" duration:2w` paints "Technology" over "Selection" inside the bar. The author's lines are authoritative: no auto-wrap runs on them and the two-line cap does not apply, so a three-line title stays in the bar (and grows it 16px per extra line when it has a meta line). If a line is too wide for the bar, the whole title spills to the right as a stacked block with its breaks kept. `\\n` shows the literal text `\n`. Elsewhere a break behaves as whitespace: the MS Project export collapses it to one space (as the Mermaid export already did), an `.xlsx` Title cell keeps an in-cell break, and `NL.I1000`, the validator's messages (`Item "Technology Selection" requires a "size:" or "duration:" property.`) and the editor outline name the item with its breaks as spaces (`@nowline/core` now exports `singleLine`). `PositionedItem.title` keeps the raw string and `titleLines` carries the lines. Rendered output changes only for titles that contain a break.
- **`@nowline/layout` + `@nowline/renderer` + `@nowline/core` + every surface — `show` draws non-working days as shaded bands** (milestone m2p phase 4, [`specs/working-calendar.md`](./specs/working-calendar.md) §4.2 and §7.3): the new roadmap style key `default roadmap non-working:show` (or `hide`, the default) draws a `calendar:business` roadmap's weekends at full width as bands behind the lanes (`<g data-layer="non-working">`, `timeline.nonWorkingFill` at 0.1 opacity), at the days and weeks scales. Bars paint across a weekend and end at the end of their last working day, so chained items show the gap; milestones and the now-line sit on their own dates; week ticks stay on Mondays and a week column is 56 px instead of 40. The schedule is the same in both views, so Mermaid, MS Project and XLSX output does not change. A render-time option overrides the key on every surface: `--non-working hide|show` on the CLI (also `--serve`), `nonWorking` in `@nowline/embed`, `@nowline/browser` and the MCP `render` and `export` tools, the `non-working` input of the GitHub Action, and a "Non-working days" menu in the preview toolbar; precedence is the option, the file's key, then `hide`. The key is validated as `NL.E0800` (EN and FR), `non-working` is a roadmap-only style key like `minor-grid`, the printer sorts it after `minor-grid`, and the TextMate grammar highlights it. `ResolvedStyle.nonWorking` is new in the positioned model. Output under `hide`, which stays the default, is byte-identical to before: every existing example, test fixture and snapshot renders unchanged. The only new bytes are the `tests/weekends-show.nowline` fixture's snapshot and its determinism cells.
- **VS Code extension — `nowline.preview.nonWorking` setting and a "Non-working days" toolbar menu**: `file` (default), `hide` or `show`; precedence is the toolbar, the setting, the file's key, then `hide`, and the toolbar's File entry means no override. Save, copy and Export match the preview. See the extension's changelog.
- **`@nowline/core` — `header-height:none` with `timeline-position:bottom` or `both` now warns (NL.W0704)**: `none` removes every timeline date strip, including the mirrored bottom one, so the combination drew no dates and said nothing. The validator now warns `"timeline-position:both" draws no dates: "header-height:none" removes every timeline date strip. Set header-height to xs, sm, md, lg or xl to show them.` (EN and FR) on the `timeline-position` value. It reads the roadmap's style the way layout does: `default roadmap`, then the style of each label on the `roadmap` line with the first label winning, then the roadmap's own `style:`, a later key winning; a style or label from an include leaves it silent. The file still validates and renders as before.

### Changed

- **`@nowline/core` — a stray `wave:` key now reports NL.W0702 instead of NL.W0700**: in a roadmap that declares no waves, a `wave:` property on any entity, including a `default` line, is still ignored, but the warning is now `"wave:" on item "a1" is ignored: this roadmap declares no waves.` (NL.W0702) instead of the generic unknown-property NL.W0700. On a `default` line it used to be silent. Files without a `wave:` key see no change. In a roadmap that declares waves, `wave` on a `default` line is the existing rule-23 error. The NL.E0411 text now also mentions that a wave's `after:` accepts an inline date.
- **VS Code extension — requires VS Code 1.128 or later** ([#68](https://github.com/lolay/nowline/issues/68)): `engines.vscode` rises from `^1.125.0` to `^1.128.0`, following the Cursor-tracking floor (Cursor has embedded VS Code 1.128 since 3.12.10). Editors on an older engine keep the extension version they already have. `@types/vscode` stays at `^1.125.0` because DefinitelyTyped published nothing between 1.125.0 and 1.134.0; the policy in `CONTRIBUTING.md` now pins the types to the newest published version at or below the floor instead of requiring an exact match.
- **`@nowline/layout` + `@nowline/renderer` — item titles wrap to two lines inside the bar before spilling right**: a title too wide for one line now word-wraps (at whitespace only, never mid-word) to at most two lines inside its bar, instead of spilling beside it, as long as the meta line fits and each line fits the bar's inner width. A wrapped title with a meta line grows the bar and its row by 16px (a two-line title with no meta line needs no extra height); the next chained item stays on the row instead of dropping to a fresh one, and a wrapped title no longer raises `NL.I1000`. A single word that is too long, a title that needs three or more lines, and a meta line that does not fit still spill to the right as before. `PositionedItem` gains an optional `titleLines`. Wrapping is always on (no new DSL property or style key), so rendered output changes for any roadmap with such a title.
- **`@nowline/layout` + `@nowline/renderer` + `@nowline/core` — the business calendar counts working days on the axis, in the window and in `length:`, and hides weekends** (milestone m2p phase 2, [`specs/working-calendar.md`](./specs/working-calendar.md)): under `calendar:business`, the default, the date axis, both day-space schedulers and `length:` count working days, so a `1w` bar and a week column are both 40 px and weekends take no room. Week ticks fall on Mondays (`Jan 05, 12, 19` instead of `Jan 05, 10, 15`); month, quarter and year ticks keep their real boundaries. Anchors, dated milestones, date pins and the now-line sit at their working day, and one dated on a weekend sits at the seam with its real date in the marker's tooltip. An item pinned to a non-working day (`date:`, `start:` or the date in `after:`) starts on the next working day and reports the new info insight `NL.I1008`. `scheduleRoadmap`, and so the XLSX Start and End, returns working-day dates, an exclusive end being the day after the last working day (Saturday for a Mon–Fri item); wave tooltips and `NL.I1007` show the exclusive end too. At the days scale a faint dotted seam marks hidden days. `PositionedTimelineScale` gains optional `nonWorkingDisplay` and `nonWorking` (`PositionedNonWorkingRun`), markers gain `hiddenDate` and `overrunDate`, and items gain `nonWorkingPin`; the theme gains `timeline.nonWorkingSeam`. The headline change is rendered output: a roadmap under `calendar:business` redraws with different tick labels, a different now-line and window end, and moved dated markers, while no item bar moves. `calendar:full` and `calendar:custom` output is unchanged. The XLSX, MS Project and Mermaid exporters read the same calendar and durations as the chart in phase 3, which ships in the same release (see the exporter entry below).
- **`@nowline/export-xlsx` + `@nowline/export-msproj` + `@nowline/export-mermaid` + `@nowline/layout` — the exporters read the file's calendar and the chart's durations** (milestone m2p phase 3, [`specs/working-calendar.md`](./specs/working-calendar.md) §8): each exporter kept its own duration table and ignored the file's calendar, so its numbers disagreed with the chart. All three now take each item's duration from the same schedule the chart uses, in the file's calendar, so XLSX and Mermaid output changes for every calendar. XLSX: the Items Duration column is that day count, the Roadmap sheet gains a `Calendar` row after `Start` (`business (Saturday and Sunday off; 5/22/65/260 days per week/month/quarter/year)`, `full (no days off; 7/30/91/365 days per week/month/quarter/year)`), `Generated` moves to row 6, and the Items `End` header reads `End (exclusive)`, as the Waves sheet already did. MS Project: a task lasts the item's days times 480 minutes (`PT2400M0S` for a business `1w`), and an item with no duration stays a one-day task. Mermaid: `Nw` is written as the day count (`Nd`, up to two decimals), so a `calendar:full` `4w` is `28d`. On `calendar:business`, Mermaid also gains `excludes saturday, sunday` after `dateFormat` with durations counted in working days, and the dates the exporter derives (the roadmap start, lane leaders, undated anchors and wave-end milestones) fall on working days; a wave that ends on a Friday gets a Monday milestone, not Saturday. Declared anchor and milestone dates are written as given. `@nowline/layout` gains `resolveWorkingCalendar(file, resolved)` and the types `ResolvedCalendar`, `CalendarConfig`, `CalendarMode` and `WorkingCalendar`; `RoadmapSchedule` gains `calendar`, `ScheduledItem` gains `days` (0 when the item has no duration), and `WorkingCalendar` gains `workingWeekdays` (the open-ended week's working weekdays, 0 = Sunday). Dated days off, MS Project `<Exceptions>` and `<WorkWeeks>`, and Mermaid date excludes come with the phase 5 declarations.
- **`@nowline/core` — style value errors carry stable codes (NL.E0801–E0803)**: an invalid `bg` / `fg` / `text` colour is now `NL.E0801`, a value outside an enumerated style key's list (`border`, `shadow`, `font` and the rest) is `NL.E0802`, and an unknown key in a `style` block is `NL.E0803`, in a `style` block and on a `default` line alike. The English text is byte-identical; what changes is the code every surface shows (the CLI, `--diagnostic-format json`, the browser diagnostics table, the MCP tools), which was the generic `validation` label (or a wrong guess such as `duration` when the key or value contained that word), and `--locale fr` now localizes these messages. The French text ships with the codes.
- **`@nowline/core` — raw style and symbol errors carry stable codes (NL.E0804–E0812)**: a raw style property on a roadmap-section entity (rule 20) is now `NL.E0804`, and the symbol rules are `NL.E0805` (id shadows a built-in icon), `NL.E0806` (missing `unicode:`), `NL.E0807` (empty `unicode:`), `NL.E0808` (`ascii:` not 1-3 ASCII characters), `NL.E0809` (unknown symbol property), `NL.E0810` (duplicate symbol id), `NL.E0811` (`icon:` / `capacity-icon:` names neither a built-in nor a declared symbol) and `NL.E0812` (symbol referenced before its declaration). The English text is byte-identical; every surface now shows the code instead of the generic `validation` label (or a heuristic guess), and `--locale fr` localizes these messages. The French text ships with the codes.

### Fixed

- **`@nowline/layout` — with several styled labels, the first label's style wins**: [`specs/rendering.md`](./specs/rendering.md) § Style Precedence says the first label in `labels:` takes precedence, but layout applied label styles in declaration order, so the last label won on any property two labels' styles both set (`labels:[enterprise, low-confidence]` drew the `low-confidence` border). Layout now applies them so the first label wins; a property only a later label's style sets still applies, and an entity's own `style:` and inline properties still override every label. Rendered output changes only for an entity whose labels' styles set the same property, such as the `examples/product.nowline` SSO item's border and the `examples/long.nowline` agent-observability bar's fill.
- **`@nowline/layout` + `@nowline/renderer` — `header-height` now sizes the timeline date strip**: the roadmap-only style key was documented and validated but ignored, so `default roadmap header-height:xl` rendered the same as `:none`. The date strip is now 16, 20, 24, 32 or 40 px for `xs` through `xl`, with its labels re-centered, for the top strip and the mirrored bottom strip (`timeline-position:bottom|both`) alike; the now-pill, wave strip, marker row and chart move with it. `header-height:none` removes every date strip, including the ones `timeline-position` asks for. `md`, the default, keeps today's 24 px strip, so files that omit the key or set `md` render byte-identically (every shipped example and snapshot). `@nowline/layout` exports `HEADER_HEIGHT_PX` (bucket to pixels, now holding the tick-panel heights) and `timelineTickLabelBaselineOffsetPx(height)`.
- **`@nowline/core` — enum style keys on a `default` line no longer accept colours**: the `default <entity>` check let any colour-shaped value through for enum keys, so `default roadmap minor-grid:#fff`, `timeline-position:red` or `border:none` validated clean while the same value in a `style` block was an error. No enum key accepts a colour (`specs/dsl.md` rule 19), and both paths now report the same single `Invalid value "…" for "…". Allowed: …` error. Files that relied on the bypass now fail validation; none of the shipped examples do.
- **`@nowline/core` — roadmap-only style keys on another entity's `default` line now warn (NL.W0703)**: `header-height`, `timeline-position`, `minor-grid` and `non-working` are read only from the roadmap's style, but `default item minor-grid:true` or `default swimlane non-working:show` validated clean and silently did nothing. They now draw the warning `"minor-grid" on "default item" is ignored: it is a roadmap-only style key. Set it on "default roadmap" instead.` (EN and FR); the file still validates and renders as before. `default roadmap` takes the keys without a warning, and `style` blocks are not checked, since one block can serve the roadmap and other entities alike. No file under `examples/` or `tests/` is affected.
- **`@nowline/cli` `--serve` + GitHub Action — the `grayscale` theme is accepted**: `nowline --serve --theme grayscale` failed with `invalid --theme`, and the Action's `theme: grayscale` input failed with `theme must be "light" or "dark"`, although `render` has accepted `grayscale` (and the `greyscale` alias) since it shipped. Both now validate against the same theme list as `render`, matching case-insensitively and taking `greyscale` as an alias; the serve page uses its light chrome for `grayscale`. An unknown name is still rejected, and the messages now list every accepted theme (`Expected light, dark, or grayscale.` from `--serve`, `theme must be one of "light", "dark", "grayscale"` from the Action). The `-t` entry in `nowline(1)` (English and French) lists `grayscale` too.
- **`@nowline/layout` — swimlane bands reach the canvas edge when the timeline extends after layout**: when content overflowed the pre-pass date window (for example a milestone diamond sitting exactly on the window's last day), the post-layout extension grew the timeline by a column, but every swimlane background kept the pre-extension width and stopped short of the tick panel and the canvas edge. Bands are now stretched after the extension. An isolated include region had the same stale width: its dashed box and nested lane bands stayed clamped to the pre-extension canvas instead of fitting its bars plus the usual right padding, and are now re-fitted once the width is final. Rendered output changes only for roadmaps where the extension fires; in the shipped samples that is `examples/platform-2026.nowline`, whose two lane bands grow from 742.64 to 782.64 px.
- **`@nowline/layout` — month, quarter, and year ticks sit on real calendar boundaries**: the date header stepped these ticks by the calendar preset's fixed day count (`calendar:full` 30, 91, 365; `calendar:business` 22, 65, 260) and labelled each one with the date it landed on. Under `calendar:full` the drift crossed a month edge after a year, so a 17-month `scale:1m` roadmap starting 2026-01-05 read `… Nov Dec Dec Jan Mar Mar Apr` instead of `… Nov Dec Jan Feb Mar Apr May`; under the default `calendar:business` it went wrong at the second tick (`Jan Jan Feb Mar Apr Apr …`, `Q1 Q1 Q2 Q3`). Ticks now fall on the 1st of each month, quarter (Jan, Apr, Jul, Oct), or year, with each column labelled from its own start, so a roadmap that starts mid-month opens with a partial column named for that month. The date window pads its right edge to the next real month / quarter / year start instead of a multiple of the preset's day count. A partial edge column too narrow for its label (a start on Mar 29, or a `length:` that ends a few days past a month start) keeps its tick but drops the label. The `calendar:` preset still sets how `1m` / `1q` / `1y` durations convert to days, so under `calendar:business` a `duration:1m` bar (22 days) is now visibly shorter than a month column; the old header hid that by sizing its columns to the bar. Day and week ticks are unchanged. Rendered output changes for roadmaps on a month, quarter, or year scale (column positions, labels, and the chart's right edge); none of the snapshotted samples use one, and `examples/showcase.nowline` (`scale:1m`, business) now reads `Jan Feb` instead of `Jan Jan Feb`.
- **`@nowline/renderer` — arrowhead markers no longer bleed between SVGs on one page**: the dependency and slack-arrow `<marker>` defs used fixed ids (`nl-arrow`, `nl-arrow-light`, `nl-arrow-dark`). When several SVGs are inlined in one HTML page, as `@nowline/embed` does for every block it finds, `url(#nl-arrow)` resolves to the first marker with that id in the document, so a dark-theme diagram below a light-theme one painted the light diagram's arrowheads. The markers now take the per-render id prefix like the shadow filters already do (`<idPrefix>-arrow`, `-arrow-light`, `-arrow-dark`; `nl-0-root-arrow` and so on by default), and every reference follows. Every SVG and HTML export's bytes change, since the markers ship in every document's `<defs>`; PNG and PDF output is unchanged. Anything that targeted `#nl-arrow` from outside the SVG needs the new id. SVGs rendered with the default prefix still share ids with each other, so callers inlining several of them should pass a distinct `idPrefix` per render, as the embed does.
- **`@nowline/core` — a diamond include contributes each entity once**: when the root reached the same file through two includes (`a.nowline` and `b.nowline` both including `shared.nowline`), the resolver merged the shared file's cached content once per path. A title-only declaration (`milestone "Launch" date:…`, `swimlane "Platform"`) landed twice under `launch` and `launch-2`, so it rendered twice, a duplicated swimlane with all its items. Explicit-id declarations and config `style` / `symbol` entries were kept once but each raised a spurious `… from b.nowline is shadowed by the parent's definition.` warning. The resolver now recognizes a declaration it has already merged and skips it silently, as `specs/dsl.md` § Diamond Includes requires. A genuine collision (an intermediate file redeclaring a shared explicit id) still warns.
- **`@nowline/export-pdf` — PDF `Subject` no longer embeds the absolute source path**: the Info dict's `Subject` defaulted to the full `sourcePath` (for example `/Users/you/src/roadmaps/plan.nowline`), despite being documented as the source filename. It now defaults to the basename (`plan.nowline`), so a shared PDF no longer reveals the author's directory layout, and the same roadmap exports to identical bytes from any directory (the `/ID` and xref offsets were derived from the path). An explicit `subject` option still wins. Every PDF export's bytes change, from the CLI, the VS Code extension and `@nowline/mcp`.
- **`@nowline/layout` — arrows and date glyphs follow a bar that layout moves down after placing it**: two layout steps move already-placed bars down, and both left geometry behind. When an item lands back on an earlier row and is taller than it (a wrapped title or label chips), that row grows and every later row of the lane or group moves down 16px or more, but the dependency arrows into and out of those rows, the milestone slack arrows from them, and the `after:DATE` / `before:DATE` calendar glyphs on their items, groups and parallels stayed at the old height. When the marker band grew a row, every item, group and parallel calendar glyph stayed one marker row (26px) above its box. Arrow and slack-arrow attach points are now read off each bar's final position, and both shifts move the glyphs with their boxes. The attach rules themselves are unchanged. Rendered output changes only for roadmaps that hit either shift; none of the shipped samples do, and `tests/late-row-shifts.nowline` now covers both.
- **`@nowline/renderer` — in-bar caption no longer overlaps the link icon**: the renderer started in-bar captions at the bar's left edge + 12px while the link-icon tile covers 6px to 20px, so the title and meta began under the tile. Captions on bars with a link icon now start at +24px, the inset layout already measured against.
- **`@nowline/layout` — an item title no longer runs under the status dot, footnote indicators or `before:` glyph**: the first title line used to extend to 12px from the bar's right edge, which put its last characters under the status dot (7 to 17px from the edge), the footnote digits and the `before:` inline-date glyph at the same height. The first line now stops 4px short of the leftmost of those that render inside the bar, so a title that previously ran under them wraps to a second line or spills to the right instead. Line 2 and the meta line sit below the decorations and keep the full inner width. Rendered output changes for any roadmap whose first title line used to reach the decorations.
- **`@nowline/layout` + `@nowline/renderer` — an item caption no longer overlaps an `after:` date glyph**: the `after:DATE` calendar glyph sits in the bar's upper-left (`bar.x + 6 .. 18`, or `24 .. 36` beside a link tile) while the caption started at +12 (+24 with a link tile), so the title's first line ran under the glyph. The caption (every title line and the meta line) now starts 4px past the glyph, at +22 or +40 with a link tile, and the wrap / spill decision measures against that inset, so a title that only just fit may now wrap or spill. A glyph that spills out of a bar narrower than 40px reserves nothing. Rendered output changes only for items with an in-bar `after:DATE`; in the shipped samples that is `tests/inline-date-corners.nowline`.
- **`@nowline/layout` — dependency arrows start at the right height when the marker band grows, and a taller wrapped bar no longer bends the arrow to its same-row neighbor**: when a milestone or anchor pushed the marker band onto a second row, the layout shifted every bar down but left each item-sourced dependency arrow's start behind, so the arrow left its source about one marker row (26px) too high. Separately, an arrow now attaches to a bar whose caption stays inside it at the row's nominal midline (28px below the bar top, as for any 56px bar) rather than at the bar's own mid-height. A bar grown by a wrapped title or label chips is taller than its row-mates, so its mid-height used to sit a few pixels below theirs and the arrow between two adjacent bars drew a small S-jog; grown and normal bars on one row now share an attach line, a straight arrow stays straight, and the layout's redundant-arrow suppression between touching same-row bars applies to grown bars too. Bars whose caption spills to the right keep their previous attach.
- **`@nowline/layout` — a milestone slack arrow leaves a grown bar level with its dependency arrows**: on a bar grown by a wrapped title or label chips, the dotted slack arrow to a milestone left at the bar's own mid-height, below the nominal row midline (28px under the bar top) where the bar's dependency arrows attach (8px below it on a bar grown by a wrapped title with a meta line), so the two kinds of arrow left the same bar at different heights. - **`@nowline/layout` / `@nowline/renderer` — inline-date glyph on a bracket-style or unstyled group or a parallel is no longer hidden under the first child bar**: these containers painted their `after:DATE` / `before:DATE` calendar glyph at the box's top corners, where the first child bar starts and is painted on top of it, so the glyph never showed. - **TextMate grammar + VS Code extension — keywords, keys and enum values no longer match inside a hyphenated word**: the keyword, property-key, include-mode, style-key and enum patterns used `\b`, which treats `-` as a word break, so `team` matched inside `platform-team` and `text:` inside an unknown `foo-text:`. - **`@nowline/layout` — timeline date-window truncation on content overflow**: a roadmap's `length:` now acts as a *minimum* timeline span rather than a hard cap. - **`@nowline/layout` — item boxes pushed past the timeline by caption spill**: a post-layout pass now walks every leaf item bar, marker, and include region (ignoring spilled captions, which are still allowed to overhang) and grows the date window to the next tick boundary when a bar/marker/include ends up past it — fixing cases where a group or swimlane's sequencing cursor, inflated by an earlier spilled caption, pushed a later block's bars out of the last column. - **`@nowline/export-xlsx` + `@nowline/export-msproj` + `@nowline/export-mermaid` — exports count durations the way the chart does**: `q`, declared `size … effort:` values and `capacity:` were ignored by the exporters (`size:med` with `effort:1w` was 0 in XLSX and one day in MS Project and Mermaid, and `capacity:2` did not shorten an item), and `q` fell back to one day or zero. - **`@nowline/layout` — a `start:` pin on an item that is a direct parallel track moves the bar**: the pixel layout ignored `start:` on an item directly inside a `parallel` block, so the bar sat at the parallel's start while the date window, `scheduleRoadmap`, every exporter and `NL.I1008` used the pin.   `node_modules`, forcing hosts to fall back to SVG and rasterize it themselves.
- **`@nowline/mcp` — in-chat preview auto-detect**: `clientSupportsAppsUi` now probes
  `capabilities.extensions` (where Claude Desktop advertises `io.modelcontextprotocol/ui`) in

- **`@nowline/mcp` — in-chat preview dimming**: the preview panel no longer shows a dark
  50 % opacity overlay and "No problems" diagnostic bar on a clean roadmap in Claude Desktop
  (and any other MCP Apps host). Root cause: `entry.ts` was calling
  `handle.setDiagnostics(result.warnings)` after every successful render; even an empty

  Fixed at two levels: (1) `mountLivePreview` uses `applyRenderResult` which never calls

### Fixed

### Fixed

- **`release.yml` npm publish loop: tighten tarball glob.** The `for pkg in …; do find dist-pack -name "${pkg}-*.tgz"; done` loop used an unanchored glob; for `pkg=nowline-lsp` the pattern matched both `nowline-lsp-0.4.0.tgz` and `nowline-lsp-worker-0.4.0.tgz`, and `find … -print -quit` returned whichever appeared first in the directory walk. In v0.4.0, the `nowline-lsp` iteration accidentally published `lsp-worker`; the next iteration (`nowline-lsp-worker`) then hit `403 already published` on its second attempt and halted the loop, leaving `@nowline/lsp`, `@nowline/config`, `@nowline/cli`, and all seven `@nowline/export-*` packages at their previous versions on the registry. The fix anchors the glob to `${pkg}-[0-9]*.tgz` so semver-prefixed tarballs match only their owning package.
- **`prepare-firebase-deploy` composite action: disable sparse-checkout cone-mode.** The composite's `actions/checkout@v6` step used the default cone-mode sparse-checkout, which rejects file-path arguments (`packages/embed/package.json`, passed by `release.yml`'s `embed-prod` caller for the deploy step's banner-version assertion). v0.4.0's deploy job failed at sparse-checkout with `fatal: 'packages/embed/package.json' is not a directory`. Setting `sparse-checkout-cone-mode: false` switches to gitignore-style patterns that accept individual files. The fixed-path entries (`.github/actions/prepare-firebase-deploy`, `${{ inputs.firebase-config-path }}`) are single-segment so cone-vs-no-cone matching behavior is identical for them; only the variable `extra-checkout-paths` input benefits.
